# CTA and revisions

## One clear ending

- Plan the final slide as a designed slide, not a sentence added to the last image.
- One main action. Avoid competing "comment, save, follow, DM" asks unless requested.
- When the user asks for a comment keyword, make the exact word the visual target: a contrasting highlight, a backed box, an outline or similar treatment that reads instantly at phone size. Use the same exact keyword in the artwork and the caption.
- Show the actual resource where useful (the checklist, template or guide itself), not a generic gift box.

## Promise only what exists

- Name the resource exactly as prepared: a template, checklist, prompt and guide are different things.
- Read the real resource before describing its contents.
- If the comment-to-DM automation, download link or delivery route is not set up and checked, do not imply it works. Make the CTA reviewable and state the missing step.
- When no resource is ready, use a "save this" or "follow for more" ending instead of inventing one.

## Preserve approved work

- Wording-only change: keep the scene. Change the type layer or make a targeted edit. Do not regenerate the image.
- Keep important figures, labels and qualifications when changing a headline.
- Keep the chosen style. A new style is a new trial, not a silent replacement.
- If the only available tool can regenerate but not edit, say so before replacing approved art.
- Keep the generated scene, the type overlay and the composite as separate files so wording can change later without new art.

## Keep versions apart

```
project/
  final/        approved files, numbered in posting order, plus caption
  alternates/   options the user may still choose
  trials/       experiments and studies
  source/       scenes, overlays, prompts, references, fonts
```

A trial never overwrites a final. A file becomes final only when the user approves that exact file.
