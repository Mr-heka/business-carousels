# Slide design

## Plan the whole slide before the first render

For every slide, decide together:

- headline wording and where it sits in genuine clear space;
- the main image or diagram and what it explains;
- relevant logos, app screens or products, and which object each belongs on;
- labels and arrows, each mapped to a specific object;
- empty space that gives the eye somewhere to rest;
- protected areas: faces, hands, the key object, real text, figures.

Describe all of that in the first generation prompt or layout. Do not make a polished background and then drop default text on top. If spelling, figures or exact fonts need fixing, render a transparent type layer from the actual font files and place it in the space the scene already planned. Keep the original scene, the overlay and the composite as separate files.

## Make the visuals teach

Choose the visual from what the slide must explain:

| The point is... | Useful visual |
| --- | --- |
| how something works | cutaway, mechanism, before/during/after |
| a change | before and after, or a progression |
| a difference | side-by-side comparison |
| a tool or result | the relevant app screen or real output, cropped to the part that matters |
| a sequence | a short step strip with real objects |
| a number | a chart or a labelled object with unit and period |

- Detailed, specific imagery beats generic icons. A pipe cutaway showing roots teaches more than a wrench icon.
- Every arrow starts at its label and lands on the thing it names. Remove arrows that connect nothing.
- Labels that repeat text already printed on an object teach nothing; label the role or the order instead.
- Never fabricate software screens, results, reviews or engagement numbers. Use genuine screenshots or label an illustration as illustrative.

## Numbers and charts

- Every figure has a unit and context: "$4.6B, 2025 revenue (USD)", not "4.6".
- **Measured charts:** heights, lengths or areas match the values. Build them in code or from a locked geometry guide and check the pixels; an image generator cannot be trusted with scale.
- **Illustrative comparisons** (sculptures, stacks, objects of different sizes): add a visible "Illustrative comparison" label when sizes are not to scale.
- Keep figures, periods and qualifications intact while making space. Whitespace never justifies deleting the context a number needs.

## Keep text readable

- Headline: short, makes the point, readable on a phone without zooming.
- Supporting line: one short sentence, only when the reader needs a bridge to the visual.
- Labels: a few words each, large enough to read at phone size. Kickers and tiny labels often fail this; enlarge any label that carries meaning.
- Roughly 25 to 40 visible words on an interior slide is a useful guide, not a rule. Split busy slides rather than shrinking type.
- Give the explanatory visual most of the slide, often about half to two thirds.
- Create whitespace by composing, not by deleting essential information.
- Place text where each image has real clear space. A fixed corner is not a layout.

## Interiors deserve cover-level care

Every slide gets the same material detail, lighting and finish as the cover. Keep font roles, headline weight, annotation style and spacing consistent across the deck while adapting placement to each scene. Repeat a character or motif only when it helps the story.
